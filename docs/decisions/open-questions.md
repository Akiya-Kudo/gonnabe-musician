以下は初期提案をもとに整理した判断待ち・検証待ちの事項です。新たな調査結果や確定事項を表すものではありません。

| 論点 | 現在の提案・仮説 | 判断に必要なこと |
| --- | --- | --- |
| 初期対象者 | 少し弾けるが練習時間が取れない社会人 | 10〜15人への聞き取りで、最近の具体的な困りごとを確認 |
| 最初の楽器 | 条件が同じなら初級ピアノ。自身の経験・監修協力も優先 | 開発者の経験、監修者の協力、試用者へのアクセスを確認 |
| 演奏との接続 | つまずきから外出練習・次回演奏確認につながると価値がある | 20〜30人の4週間試用と演奏の前後評価 |
| 教材 | 1楽器、短い教材20〜30本、自作または権利確認済み、監修あり | 監修者、具体的な教材、各素材の権利を確認 |
| リズム採点 | 定義済みデータと計算、遅延補正、精度が不安定なら細かい点数を控える | 対象端末・イヤホンで実機検証し、採点の扱いを決める |
| サービス名 | 仮称「ひとふし」、タグライン案「次に弾くのが、楽しみになる。」 | 名称の採否、商標・ドメインの確認 |
| 価格・提供形式 | 月額980円の例。期間のあるプログラムも候補 | 実際の有料継続を確認し、対象者・形式・料金を見直す |
| 検証基準 | 20人中8人が4週目も週3日利用、5人が有料継続という仮基準 | 実施前に母数・計測定義・確認時点を固定 |
| 開発期間・費用 | 週20時間・経験・監修者の前提で、合計10〜14週間、各予算は仮置き | 実際の稼働と協力体制、教材・運営コストを確認 |
| プロダクトの具体的な技術構成 | ホーム画面に追加できるWebアプリの案 | 要件と試作から選定。Supabase・Cloudflareは参考情報に留まる |
| 後続機能 | 和音・構造は追加、曲連携・録音評価は検証後 | 初期価値、精度、開発負担、権利処理を評価 |

## 構想に追加した運用上の検討事項

以下は原文の明示事項ではなく、今後の設計で確認したい追加論点です。

- 回答履歴・練習メモ・将来の録音について、取得目的、保存先、保持期間、削除方法をどう設計するか。
- 「少し弾ける」「次の演奏に役立った」を、参加条件や評価項目としてどう具体化するか。
- 端末変更やオフライン利用時のデータ同期、アクセシビリティ、音を出せない環境での体験をどう検証するか。

決定した事項は根拠と見直し条件を記録し、この一覧の状態も更新します。[ナレッジベースの育て方](../guide/knowledge-base.md)を参照してください。
