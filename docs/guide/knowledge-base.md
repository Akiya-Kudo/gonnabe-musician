## 基本方針

プロジェクトの構想、サービス設計、アイデア、調査、検証結果、意思決定をリポジトリ直下の **`docs/` にMarkdownで集約**します。Webサイトはこのコンテンツを読み込み、アプリ側へ記事を複製しません。

テーマ別資料を現在の方針として育て、根拠となる原文や調査記録を残します。今回の整理は初期提案の保存が出発点であり、以後の実験結果によって変更できます。

## 置き場所

| フォルダ | 置く内容 |
| --- | --- |
| `operations/` | AIエージェントの自律運用、Git・PR・CI/CD、情報保護と権限の方針 |
| `product/` | 提供価値、対象者、学習体験、機能、ブランド |
| `engineering/` | 技術方針、設計、開発・公開の手順 |
| `business/` | 検証計画、価格、ロードマップ、費用、運営 |
| `research/` | 参照資料、競合、インタビューや実験の記録 |
| `decisions/` | 未決事項と、その後の意思決定 |
| `guide/` | ナレッジベースの運用ルール |
| `sources/` | 元資料の保存。機微情報や公開権限のない資料は置かない |

## 資料の状態を明記する

- **提案・仮説**：検討中のアイデアや、まだ確かめていない見立て。
- **計画値**：人数、期間、予算、価格、基準など、条件付きで置く数値。
- **観察・検証結果**：実施日、対象、方法、結果、制約とともに記録したもの。
- **決定**：採用した方針と、その理由・根拠・見直し条件。
- **未確認**：権利、価格、商標、技術適合性など、確認が済んでいないもの。

AI生成の下書きも同じルールで扱い、根拠や確認範囲を明記します。提案をいつの間にか確定事項へ変えないようにします。

プロジェクト全体の役割分担や作業の進め方は[プロジェクト運用方針](../operations/index.md)に従います。

## 更新の流れ

1. 対応するテーマのMarkdownを追加・更新する。
2. 冒頭にタイトル・説明を設定し、提案・根拠・未決事項が分かる文章にする。
3. 関連資料へ相対リンクを張り、必要に応じて一覧やナビゲーションを更新する。
4. 原文の引用や計画値を変えるときは、元の出典と変更理由を残す。
5. ドキュメントサイトをビルドし、リンクと表示を確認して変更をレビューする。

新しい資料の基本形は次のとおりです。

```md
---
title: 資料のタイトル
description: この資料で分かること。
---

現在の状態、目的、前提を記載します。

## 内容

提案・設計・結果を記載します。

## 根拠と未決事項

参照先、確認範囲、次に確かめることを記載します。
```

## 意思決定を残す

後で判断の理由が追えるように、決定には日付、状態、背景、選択肢、採用案、理由、影響、見直し条件を記録します。必要になった時点で `decisions/` に個別のMarkdownを追加し、[未決事項](../decisions/open-questions.md)と関連資料も更新します。

## 原文と公開範囲

[初期提案の原文](../sources/initial-proposal.md)は照合用に保持し、方針の更新はテーマ別資料へ反映します。原文に訂正が必要な場合は、訂正であることを示して経緯を残します。

Vercelから公開される `docs/` には、秘密情報、未許諾の教材、個人を特定できる利用者情報を含めません。調査結果は公開範囲に合った形で記録します。
